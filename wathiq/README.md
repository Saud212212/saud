# وثيق | Wathiq

مساعد ذكي للمنافسات الحكومية السعودية: من كراسة الشروط إلى مصفوفة امتثال موثّقة وعرض فني جاهز.

> مشروع مستقل تماماً داخل هذا المجلد (package.json و docker-compose و .env خاصة به)، ولا يعتمد على أي شيء خارجه.

## الحالة: المرحلة 1 مكتملة — الرفع والاستخراج

| المرحلة | الحالة |
|---|---|
| 1. الرفع والاستخراج | ✅ |
| 2. الملخص ومصفوفة الامتثال | ⏳ يحتاج نص البرومت النظامي (انظر `prompts/`) |
| 3. ملف الشركة وتحليل الفجوات | — |
| 4. العرض الفني والتصدير | — |
| 5. الحسابات والاشتراكات | — |

### ما أُنجز في المرحلة 1
- **الرفع:** عدة ملفات PDF لكل منافسة (كراسة، ملاحق، جداول كميات). يُتحقق من أنها PDF فعلاً بتوقيع الملف لا بالامتداد، ثم تُشفّر بمفتاح المنافسة قبل التخزين.
- **تصنيف كل صفحة على حدة:** نصية، ممسوحة، مختلطة (نص مع صورة كبيرة)، طبقة نص تالفة (ترميز عربي خاطئ)، فارغة.
  - يُكشف ختم أو تذييل نصي فوق صورة ممسوحة، فتُعامل الصفحة كممسوحة.
  - يُكشف النص المحوّل إلى منحنيات.
  - تُتجاهل صور الترويسة المتكررة في كل الصفحات.
- **استخراج النص مع إحداثيات كل كلمة:**
  - الصفحات النصية تُقرأ من طبقة النص عبر pdf.js، مع إعادة بناء عربية مبنية على المواضع الفعلية للحروف. هذا يعالج ملفات PDF التي تخزّن الحروف بترتيب بصري، وأشكال العرض (Presentation Forms)، و"لأ"، والتشكيل، والأرقام والإنجليزية داخل سطر عربي.
  - الصفحات الممسوحة تمر بـ OCR (Tesseract للعربية والإنجليزية بنماذج tessdata_best) خلف واجهة قابلة للاستبدال، مع درجة ثقة لكل كلمة ولكل صفحة. الصفحات الضعيفة تُعلَّم ويُنبَّه المستخدم.
- **التقسيم إلى مقاطع:** عند حدود البنود (2.1، المادة، أولاً:، القسم)، ويحتفظ كل مقطع برقم الصفحة ومواضع النص فيها.
- **طابور مهام وشريط تقدم:** طابور فوق Postgres (بلا Redis)، وعامل مستقل، وتقدم حي عبر SSE بمراحل واضحة.
- **الحذف النهائي:**
  - إتلاف مفتاح المنافسة، ثم حذف الملفات، ثم حذف كل الصفوف.
  - يُسجَّل الحذف في سجل التدقيق بلا محتوى.
  - الحدود الدقيقة في [`docs/security.md`](docs/security.md).
- **عزل الشركات:** RLS مفروض، ودور غير مالك للجداول، ومفاتيح أجنبية مركّبة، مع اختبار آلي يشمل مهام العامل.
- **الواجهة:** عربية أولاً RTL مع الإنجليزية.
  - رفع بالسحب مع تقدم الرفع.
  - صفحة المنافسة: تقدم حي، ولوحة تصنيف الصفحات، وتنبيه الصفحات الضعيفة.
  - **عارض الصفحة:** الصفحة الأصلية مع مربعات الكلمات المستخرجة. التمرير على كلمة في النص يظلّل موضعها في الصفحة والعكس. هذا هو الأساس لتظليل الاقتباسات في المرحلة 2.
- **`eval/`:** هيكل جاهز لقوائمك المرجعية مع مخطط ومدقّق.

## التشغيل

### بـ Docker (الأسهل)
```bash
cd wathiq
cp .env.example .env
# املأ WATHIQ_MASTER_KEYS و SESSION_SECRET:
#   echo "WATHIQ_MASTER_KEYS=k1:$(openssl rand -base64 32)" >> .env
#   echo "SESSION_SECRET=$(openssl rand -hex 24)" >> .env
docker compose up --build
```
ثم افتح http://localhost:3100 واختر حساباً تجريبياً.

### محلياً (للتطوير)
المتطلبات: Node 22+، PostgreSQL 16، `tesseract-ocr`، `poppler-utils`. ويُنصح بنماذج [tessdata_best](https://github.com/tesseract-ocr/tessdata_best) للعربية.
```bash
npm install
# مرة واحدة كـ superuser: الأدوار + قاعدة يملكها wathiq_owner
psql -U postgres -f infra/postgres/init-roles.sql
psql -U postgres -c "create database wathiq owner wathiq_owner"
cp .env.example .env         # واملأ المفاتيح
npm run db:migrate && npm run db:seed
npm run dev                  # الواجهة على :3100
npm run worker               # في طرفية أخرى
```

## كيف تختبر المرحلة 1

### آلياً
```bash
npm test          # 41 اختباراً: وحدات + تكامل على Postgres حقيقي
npm run typecheck
```
اختبارات التكامل تنشئ قاعدة `wathiq_test` نظيفة في كل تشغيل، وتحتاج Postgres بصلاحية superuser:
`TEST_ADMIN_DATABASE_URL` (الافتراضي `postgresql://postgres@127.0.0.1:5433/postgres`).

| معيار القبول | الاختبار |
|---|---|
| رفع كراسة نصية وممسوحة ومختلطة | `pipeline.test.ts › uploads a text, a scanned and a mixed booklet` |
| تصنيف كل صفحة بشكل صحيح | `pipeline.test.ts › classifies every page correctly` + `pdf-classify.test.ts` |
| استخراج النص مع إحداثيات الكلمات | `pipeline.test.ts › extracts text with word coordinates` + `pdf-classify.test.ts` + `ocr.test.ts` |
| ظهور شريط التقدم | `pipeline.test.ts › reports increasing progress … until 100%` |
| حذف نهائي يعمل | `pipeline.test.ts › hard delete` (3 اختبارات) |
| عزل الشركات بما فيه العامل | `rls.test.ts` (9 اختبارات) |

### يدوياً
1. `npm run fixtures` يولّد ثلاث كراسات عربية تجريبية في `tests/fixtures/`: نصية، وممسوحة، ومختلطة (صفحتان نصيتان وصفحتان ممسوحتان، إحداهما عليها ختم نصي). وهي موجودة مسبقاً في المستودع.
2. ادخل باسم **سارة العتيبي (مالك)** ← «منافسة جديدة» ← ارفع الملفات الثلاثة.
3. راقب شريط التقدم ومراحله.
4. في صفحة المنافسة: الصفحات النصية بالأخضر، والممسوحة بالذهبي مع نسبة ثقة OCR.
5. افتح أي صفحة ومرّر المؤشر على كلمة في النص المستخرج، وسيُظلَّل موضعها في الصفحة.
6. «عرض المقاطع» يعرض المقاطع بأرقام صفحاتها وبنودها.
7. «حذف نهائي» ← اكتب «حذف». بعدها رابط المنافسة يُرجع 404.
8. للتحقق من العزل: ادخل باسم **ريم القحطاني** (شركة أخرى)، فلن ترى منافسات سارة، وفتح رابطها المباشر يُرجع 404.
9. جرّب **خالد الشهري (محرر)**: يستطيع الرفع، ولا يظهر له زر الحذف النهائي (والـ API يرفضه أيضاً).

جرّب أيضاً كراسات حقيقية من منصة اعتماد، ولاحظ الصفحات المعلَّمة بثقة منخفضة.

## قرارات تغيّرت عن وثيقة التصميم
| التصميم | التنفيذ | السبب |
|---|---|---|
| pg-boss | طابور بسيط فوق Postgres (`job_queue` + `FOR UPDATE SKIP LOCKED`) | لا صلاحيات إنشاء مخطط إضافي، وفصل واضح بين المطالبة (بلا محتوى) والمعالجة (تحت RLS) |
| MinIO | SeaweedFS في docker-compose | MinIO توقف عن نشر صور Docker للنسخة المجتمعية. الكود يعمل مع أي مزود S3 |
| مفاتيح أجنبية بسيطة | مركّبة `(org_id, id)` | فحوص FK تتجاوز RLS |
| Better Auth | دخول تجريبي مؤقت بكوكي موقّعة | المصادقة الحقيقية في المرحلة 5 كما طلبتم. البنية (org_id + RLS + الأدوار) جاهزة من الآن |

## ملاحظات OCR
- نماذج `tessdata_best` أدق بوضوح للعربية من نماذج حزم النظام. في الاختبار: النماذج المرفقة بالنظام أسقطت سطراً كاملاً من صفحة، والنماذج الأفضل التقطته. حاوية العامل تنزّلها تلقائياً.
- `OMP_THREAD_LIMIT=1` لكل عملية Tesseract والتوازي بين الصفحات. بدونه، صفحتان بالتوازي استغرقتا أكثر من 3 دقائق بسبب تزاحم الخيوط، ومعه 1.5 ثانية.
- الضعف المعروف: علامة % بجوار الأرقام قد تُقرأ خطأ ("%40" ← "9640"). هذه أخطاء OCR حقيقية تظهر للمستخدم بثقة الكلمة. المرحلة 2 تتعامل معها بالمطابقة التقريبية ووسم "يحتاج مراجعة".
